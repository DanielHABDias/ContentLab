              Motion design: cenas contínuas
              
        
              O JSON 0.2 já permite um fundo estático que permanece enquanto PNGs e textos aparecem, se movem e são revelados pela câmera virtual. Use keyframes de posição, escala, rotação e opacidade. O JSON 0.1 continua funcionando para a edição tradicional.
              
        
              Esta é a primeira versão: vídeos dentro da cena, legenda cinética e ajuste visual dos keyframes ainda não fazem parte do 0.2. Veja MOTION_DESIGN_PLAN.md e examples/motion-design-proposal.v0.2.json no repositório. Para fundos sólidos use background.color; para arquivos próprios use project://, e para mídia interna use builtin:// após adicionar os arquivos à biblioteca.
              
      
              
      
              
        
              1. Organize uma pasta por vídeo
              
        
              Você pode começar com uma pasta vazia: transcreva a narração primeiro e crie edit_plan.json depois, com a IA. Se preferir preparar a base antecipadamente, use Editor automático → Criar. A estrutura final fica assim:
              
        
              meu-video/
├── edit_plan.json              plano de edição
├── audio/
│   ├── narracao.wav            voz
│   ├── musica.mp3              música opcional
│   └── impacto.wav             efeito opcional
├── assets/
│   ├── abertura.mp4            vídeo ou imagem
│   ├── personagem.png
│   └── personagens/
│       └── heroi.png           subpastas funcionam
├── transcript.json             tempos por palavra
├── transcript.txt              leitura humana
├── transcript.srt              legendas
└── output/                     gerado após render
              
        
              Os nomes são exemplos; escolha os seus. O JSON deve usar exatamente o caminho do arquivo real.
              
      
              
      
              
        
              2. Referencie os arquivos no JSON
              
        
              audio.narration usa caminho relativo ao projeto. Imagens, vídeos, músicas e efeitos usam project:// seguido do caminho desde a raiz do projeto.
              
        
              {
  "sources": {"assets": "assets", "transcript": "transcript.json"},
  "audio": {
    "narration": "audio/narracao.wav",
    "music": [{"asset": "project://audio/musica.mp3", "start": 0, "end": 30}]
  },
  "timeline": [{
    "id": "intro", "start": 0, "end": 5,
    "elements": [
      {"type": "video", "asset": "project://assets/abertura.mp4"},
      {"type": "image", "asset": "project://assets/personagens/heroi.png"}
    ]
  }]
}
              
        
              O nome e a extensão precisam corresponder ao arquivo, inclusive maiúsculas/minúsculas no Linux. Use / nos caminhos também no Windows. sources.assets não completa automaticamente os caminhos dos elementos.
              
      
              
      
              
        
              3. Confira antes do render
              
        
              No Editor automático, use Listar para ver os URIs e Validar JSON para identificar arquivos ausentes. A transcrição é opcional para um corte comum, mas necessária para karaoke e útil para texto cinético sincronizado.
              
        
              Arquivos que acompanham o aplicativo usam builtin://. Arquivos seus usam project://. Caminhos que saem da pasta do projeto são bloqueados.
